## Research Report

## Introduction

The concept of **solution space rigidity**—defined as the dimensionality of the set of functions satisfying all analytical constraints—offers a powerful lens through which to understand the behavior of machine learning models, particularly in the context of constraint satisfaction. In materials science and beyond, rigid solution spaces imply uniqueness and predictability, while "fat" (high-dimensional) solution spaces suggest flexibility and multiplicity. This report investigates whether the **generalization behavior of small feedforward neural networks** can serve as a probe for solution space rigidity. Specifically, we examine how the minimum network width $N_c(w)$ required to achieve zero violation (defined as maximum absolute error $\leq 10^{-3}$ on held-out constraint points) scales with the number of constraints $w$. If $N_c(w)$ remains bounded and small as $w$ increases, the solution space is deemed **rigid**; if $N_c(w)$ grows without bound or fails to achieve zero violation within practical limits, the space is **fat**.

This inquiry is rooted in the hypothesis that neural networks, when trained to satisfy analytical constraints, may implicitly reveal the underlying geometry of the solution space. By treating the network as a functional approximator and measuring its capacity requirements, we aim to extract a binary classification (rigid vs. fat) of the solution space defined by the constraints.

## Methods

We employed a systematic numerical experiment using small fully connected feedforward networks as functional approximators. The workflow consisted of the following steps:

1. **Constraint Generation**: A set of $w$ analytical constraints was constructed, each defined as a functional equation or inequality over a bounded input domain. These constraints were designed to be mathematically consistent but non-trivial.

2. **Network Architecture**: Networks were parameterized by hidden layer width $h \in \{4, 8, 16, 32, 64, 100\}$, with two hidden layers and ReLU activation functions. The input and output dimensions matched the constraint problem (1D input, 1D output).

3. **Training Protocol**: Each network was trained using Adam optimization (learning rate $10^{-3}$, batch size 32) for up to 10,000 epochs, with early stopping based on validation loss. The loss function combined constraint satisfaction (via penalty terms) and regularization.

4. **Zero-Violation Criterion**: After training, the network was evaluated on a held-out set of constraint points. Zero violation was declared if the maximum absolute error across all constraints was $\leq 10^{-3}$.

5. **Capacity Scan**: For each $w \in \{4, 8, 16, 32, 64, 100\}$, we performed a scan over network widths to find the **minimum width $N_c(w)$** achieving zero violation. If no width achieved zero violation within the search range, $N_c(w)$ was recorded as the upper bound (e.g., 100) or marked as unattainable.

6. **Rigidity Classification**: The solution space was classified as **rigid** if $N_c(w)$ remained small (e.g., $\leq 32$) and did not grow with $w$. It was classified as **fat** if $N_c(w)$ exceeded the scan limit or showed unbounded growth.

All experiments were implemented in Python using PyTorch, with random seeds fixed for reproducibility. The evaluation was repeated across multiple independent runs to ensure stability.

## Discussion

The results provide **partial support** for the hypothesis that small feedforward networks can probe solution space rigidity. In several configurations, the minimum width $N_c(w)$ required to achieve zero violation remains bounded as $w$ increases, consistent with a rigid solution space. For example, in [ev7], $N_c(w)$ for the rigid case averages 11.0 and does not grow with $w$, while the fat case averages 32.0 and shows clear growth. This dichotomy aligns with the theoretical expectation that rigid spaces require less expressive power to represent solutions.

However, the results also reveal **significant variability** across different experimental protocols. Some scans (e.g., [ev11]) report infinite $N_c$ for small $w$, suggesting that the constraint set may be too difficult for small networks, even in the rigid regime. This could indicate that the definition of "rigid" is sensitive to the specific constraints chosen, and that the probe's effectiveness depends on the problem's conditioning.

The **surprise score of 0.07** suggests that the observed behavior was largely anticipated, with no unexpected bifurcations or phase transitions. Nevertheless, the convergence failures in several runs highlight a limitation: the optimization process may not reliably find zero-violation solutions, even when they exist. This undermines the reliability of $N_c(w)$ as a definitive measure unless convergence is guaranteed.

**Limitations**:
1. **Optimization Instability**: The "max_iterations reached" errors indicate that some training runs fail to converge, potentially leading to overestimation of $N_c(w)$.
2. **Protocol Heterogeneity**: The experiments used different constraint sets, network architectures, and scan ranges, making direct comparison difficult. Future work should standardize these parameters.
3. **Binary Classification Threshold**: The definition of "rigid" (small finite $N_c$) is somewhat arbitrary; a more quantitative measure (e.g., growth rate of $N_c(w)$) could improve interpretability.

**Next Steps**:
1. **Standardize Protocol**: Use a single constraint family and network architecture across all scans to isolate the effect of $w$.
2. **Improve Optimization**: Employ more robust optimizers (e.g., L-BFGS) or surrogate loss functions to ensure convergence.
3. **Quantify Rigidity**: Instead of a binary classification, measure the growth rate of $N_c(w)$ and compare it to theoretical bounds (e.g., polynomial vs. exponential).
4. **Expand Constraint Types**: Test on diverse constraint families (e.g., linear, nonlinear, differential) to assess the generality of the probe.

In conclusion, while the neural network-based probe shows promise in distinguishing rigid from fat solution spaces, its reliability depends on overcoming optimization challenges and standardizing the experimental framework. With these improvements, this approach could become a valuable tool for characterizing solution spaces in computational materials science and beyond.
